📊 Sensor Dashboard – Schnittstellendokumentation
Thermokon IoT Tools · Node-RED HTML-Plugin
Version 1.0 · April 2026
ℹ️ 1. Übersicht

Das Sensor Dashboard ist eine eigenständige HTML-Seite, die Echtzeit-Sensordaten von Thermokon LoRaWAN-Geräten visualisiert. Sie kann direkt im Browser geöffnet oder als HTML-Plugin in Node-RED über einen ui_template-Node eingebunden werden.

Enthaltene Features

🃏
8 KPI-Karten
Temperatur, Feuchte, CO₂, VOC, Luftdruck, Helligkeit, RSSI, Batterie
🚦
Ampel-Färbung
Karten färben sich grün / gelb / rot nach konfigurierbaren Grenzwerten
📈
3 Verlaufsgraphen
Temperatur, Feuchte, CO₂ – letzte 30 Messwerte via Chart.js
🔔
Alarm-Log
Automatisch bei Grenzwertüberschreitung, mit Zeitstempel
📶
Signal- & Batteriebalken
Visuelle Anzeige der Signalstärke und Batteriespannung
🎭
Demo-Modus
Simulierte Zufallsdaten, solange kein echtes Signal eintrifft
📱
Responsiv
Optimiert für Desktop, Tablet und mobile Geräte
🔌
Node-RED kompatibel
Direkte Integration via ui_template oder iframe
🔌 2. Integration in Node-RED

Variante A – ui_template (empfohlen)

Node-RED Dashboard installieren
Im Node-RED Manager: node-red-dashboard installieren oder via Terminal: npm install node-red-dashboard
ui_template-Node anlegen
Einen ui_template-Node in den Flow ziehen und öffnen.
HTML-Inhalt einfügen
Den gesamten Inhalt der Datei iot-apps/sensor-dashboard/sensor-dashboard.html in das Template-Textfeld einfügen. Größe im Dashboard-Tab auf gewünschte Breite × Höhe setzen.
Datenquelle verbinden
Einen Eingabe-Node (z. B. mqtt in, http in oder inject) mit dem ui_template-Node verbinden. Das msg.payload muss das JSON-Format aus Abschnitt 3 einhalten.
Deploy & öffnen
Flow deployen → Dashboard unter http://<node-red-host>:1880/ui aufrufen.

Variante B – Iframe / HTTP-Node

Das Dashboard kann auch als statische Seite über einen http in-Node ausgeliefert und in einem <iframe> eingebettet werden. In diesem Fall werden Daten über die globale JavaScript-Funktion window.receiveSensorData(payload) übergeben: 

// Aus einem anderen Frame oder Script aufrufen:
document.getElementById('dashboard-frame').contentWindow
    .receiveSensorData({ temperature: 22.4, humidity: 46.3 });
📦 3. msg.payload – Datenformat

Das Dashboard erwartet ein JSON-Objekt als msg.payload. Alle Felder sind optional – nicht vorhandene Werte werden als — angezeigt.

{
  "deviceName":  "Sensor 01",         // Anzeigename im Dashboard
  "devEUI":      "A81758FFFE050D2C",  // LoRaWAN Device EUI
  "gateway":     "GW-Dach",          // Gateway-Bezeichnung
  "temperature": 22.4,               // °C
  "humidity":    46.3,               // % relative Feuchte
  "co2":         910,                // ppm
  "voc":         75,                 // IAQ-Index 0–500
  "pressure":    1013.2,             // hPa
  "lux":         340,                // lux
  "rssi":        -82,                // dBm (negativ)
  "battery":     3.24                // V  (Bereich 2.9 – 3.6 V)
}

Feldreferenz

Feld Typ Einheit Pflicht Beschreibung
deviceName String – Nein Anzeigename des Geräts in der Geräteleiste
devEUI String – Nein LoRaWAN Device EUI (16 Hex-Zeichen)
gateway String – Nein Bezeichnung des empfangenden Gateways
temperature Number °C Nein Lufttemperatur, 1 Dezimalstelle
humidity Number %rF Nein Relative Luftfeuchte, 1 Dezimalstelle
co2 Number ppm Nein CO₂-Konzentration, ganzzahlig
voc Number IAQ Nein Luftqualitätsindex 0–500 (Bosch BME680 IAQ)
pressure Number hPa Nein Luftdruck, 1 Dezimalstelle
lux Number lux Nein Beleuchtungsstärke, ganzzahlig
rssi Number dBm Nein LoRaWAN Empfangspegel (negativer Wert, z. B. −82)
battery Number V Nein Versorgungsspannung; Bereich 2,9–3,6 V für Balkenanzeige
🚦 4. Grenzwerte & Alarmlogik

Jede KPI-Karte färbt sich automatisch anhand vordefinierter Grenzwerte. Bei Überschreitung wird automatisch ein Eintrag im Alarm-Log angelegt. Die Grenzwerte sind im <script>-Block des Dashboards im Objekt LIMITS anpassbar.

Messgröße Einheit Grün (OK) Gelb (Warnung) Rot (Alarm)
Temperatur °C 18 … 26 °C 15 … 18 oder 26 … 30 °C < 15 oder > 30 °C
Rel. Feuchte %rF 30 … 60 % 20 … 30 oder 60 … 70 % < 20 oder > 70 %
CO₂ ppm < 1000 ppm 1000 … 1499 ppm ≥ 1500 ppm
VOC / IAQ IAQ < 150 150 … 299 ≥ 300
RSSI dBm > −100 dBm −100 … −109 dBm ≤ −110 dBm
Batterie V > 3,1 V 3,0 … 3,1 V ≤ 3,0 V

Grenzwerte anpassen

Das Objekt LIMITS befindet sich im <script>-Abschnitt der Datei sensor-dashboard.html:

const LIMITS = {
  temperature: { warn: [18, 26],  err: [15, 30]  },
  humidity:    { warn: [30, 60],  err: [20, 70]  },
  co2:         { warn: 1000,      err: 1500       },
  voc:         { warn: 150,       err: 300        },
  battery:     { warn: 3.1,       err: 3.0        },
  rssi:        { warn: -100,      err: -110       },
};
🧩 5. JavaScript-API
Funktion / Variable Sichtbarkeit Beschreibung
window.receiveSensorData(data) global Übergibt ein JSON-Objekt (oder JSON-String) an das Dashboard. Beendet automatisch den Demo-Modus.
applyData(d) intern Interne Hauptfunktion zur Darstellung eines Datensatzes. Wird von receiveSensorData und dem Node-RED scope.$watch-Hook aufgerufen.
clearAlarms() global Leert den Alarm-Log. Wird auch durch den „Leeren"-Button im Dashboard aufgerufen.
addAlarm(level, msg) intern Fügt einen Alarm-Eintrag hinzu. level: 'warn' oder 'err'.
LIMITS global Konfigurationsobjekt für Grenzwerte. Kann vor dem ersten Dateneingang überschrieben werden.
history intern Ringpuffer-Objekt für Chart-Verlaufsdaten (max. 30 Werte, konfigurierbar via MAX_HIST).

scope.$watch (AngularJS / Node-RED)

Im Node-RED ui_template-Kontext steht das AngularJS-scope-Objekt zur Verfügung. Der Hook ist bereits im Dashboard integriert:

scope.$watch('msg', function(msg) {
  if (!msg || !msg.payload) return;
  applyData(typeof msg.payload === 'string'
    ? JSON.parse(msg.payload) : msg.payload);
});
💡
Wird das Dashboard außerhalb von Node-RED geöffnet (z. B. direkt im Browser), startet automatisch der Demo-Modus mit simulierten Zufallsdaten im 5-Sekunden-Takt. Er stoppt, sobald receiveSensorData() aufgerufen wird.
